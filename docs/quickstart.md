# 两分钟完成第一批资料

这份指南使用单独下载的合成示例，工作台不会自动加载示例或测试批次。所有图片都是占位示意图，不是客户资料，也不代表工具能从画面认出商品。

## 下载

在 [Releases](https://github.com/Yixun-ai/-/releases) 下载适合自己电脑的桌面包，以及可选的 `SKU-Kit-demo.zip`。解压程序包和示例包；Windows 运行 `Start SKU Kit.bat`，Apple Silicon Mac 运行 `Start SKU Kit.command`。需要完整保留程序目录中的 `_internal` 文件夹。

若当前旧版 Release 尚无示例包，可使用已有产品表与图片，或在源码仓库根目录生成示例：

```sh
python3 scripts/make_demo.py --output demo-data
```

输出目录已存在时会拒绝覆盖。生成的资料默认被 `.gitignore` 排除；没有 Python 的普通用户等待带示例 ZIP 的 Release 即可，无需为了示例另装 Python。

## 先完成一次正常交付

1. 选择示例包中的 `clean/products.csv`。
2. 选择 `clean/images` 文件夹；编号列是 `SKU`，保持“文件名就是产品编号”。
3. 点击“检查这批资料”。应显示 2 条产品、2 张匹配图片、没有需要处理的问题。
4. 在“看图核对”中查看两张图，再下载整理好的资料包。
5. ZIP 内有 `products/001/001.png`、`products/002/002.png`、原始 CSV，以及检查报告。可在页面底部“核验已有的交付包”重新核验该 ZIP。

## 再练习一次需要确认的资料

点击“新的一批”，确认清空当前选择后，改选 `needs-review/products.csv` 和 `needs-review/images`。

这次 `待确认.png` 没有编号，002 会显示缺图，程序会阻止交付。本示例明确约定浅色示意图属于 002：点击该图片的“调整归属”，选择 002，再次检查即可通过。现实业务中，归属应由掌握商品信息的人确认，不能只因图片颜色相似就分配。

保存进度会下载包含原表、图片和确认记录的 `.sku-kit.json` 文件；之后点击“打开进度”即可继续，原始资料会重新检查。

## 换成自己的资料

表格首行是列名，编号以文本保存，图片文件名使用完整编号。例如编号 `001` 对应 `001.png`；需要后缀规则时显式选择 `001_主图.png` 这一类命名方式。多张工作表或多个编号候选列必须自己选择。

常见问题见[排障](troubleshooting.md)，完整规则见[使用说明](../sku-kit/README.md)。运行和保存进度都不需要把商品资料发给维护者。
