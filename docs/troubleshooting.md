# 常见问题

## 下载后启动不了

先完整解压 ZIP，再运行启动脚本；不要在压缩软件的预览窗口内直接运行，也不要只拷贝 `.exe`。确认 `_internal` 文件夹还在。

Windows 包面向 Intel/AMD 64 位系统，macOS 包面向 Apple Silicon。Intel Mac 暂时使用源码方式。当前桌面包未商业签名和公证；系统可能拦截首次启动。核对仓库来源和 `.sha256` 后，按系统自身提供的打开方式处理，不要关闭整机安全设置。

## 浏览器没有自动打开 / 显示无法连接

保留启动终端，从中复制 `http://127.0.0.1:端口` 地址。默认端口每次可能不同，应使用这次启动显示的地址；`127.0.0.1` 只能在运行程序的这台电脑访问。关闭启动窗口后，需要重新启动程序。

## 端口被占用

源码运行时去掉固定端口，`python3 server.py` 会自动选空闲端口。安装包方式可运行 `sku-kit --no-open`，同样自动选端口。只有需要固定地址时才添加 `--port 18766`。

## SKU 前导零不见了 / 数字或公式编号被拒绝

工具不会猜测 Excel 已经丢掉的前导零或数字精度。把原表编号列设置为文本，并从真实业务来源重新填入完整编号；把错误显示的数字简单改成文本格式，不能恢复已经丢失的内容。公式结果也不能充当可靠编号。

## 文件名看上去一样却没有匹配

默认文件名主体必须完整等于编号，空格、大小写、Unicode 形式都可能有影响。先看原表前 3 行与文件名，检查是否含前后空白。只有自己的命名规范允许时才开启“不区分大小写”或后缀模式。存在多个可能编号时由人确认，程序不会选一个看上去最像的结果。

## 明明是同一个商品，为什么重复编号不允许

默认把重复编号视为问题。确认同一商品在表里有多条记录后，可在高级选项选择“同一商品的多条记录”；产品名称冲突的重复编号仍会阻止交付。

## 资料超过网页限制

网页输入最多 50 MB，ZIP 核验最多 70 MB。更大的资料可拆批，或使用 CLI：图片总量 240 MB，交付包核验压缩与展开总量各 320 MB；具体数量和单文件限制见[使用说明](../sku-kit/README.md)。不要通过改浏览器数字或清除报错来绕过限制。

## 下载包核验通过，为什么商品仍可能拍错

SHA-256 和 CRC 核验确认包内文件与清单一致。清单没有数字签名，不证明发送者身份；图片能打开、编号能对应，也不证明画面中的商品拍对了。

## 如何反馈

使用 [Bug 表单](https://github.com/Yixun-ai/-/issues/new?template=bug_report.yml)，提供版本、系统、启动方式、复现步骤和完整报错文字。用合成或脱敏文件复现，不要上传客户表、原图、进度文件或密钥。支持范围见[SUPPORT.md](../SUPPORT.md)。
